# Architecture

What `dd-chords-pwa` is, how the data flows, and where the sharp edges are.
Agent-facing rules are in [`AGENTS.md`](../AGENTS.md); mutable state is in [`LEDGER.md`](LEDGER.md).

## What it is

A single-page PWA that serves song lyrics with chords. There is **no backend**: the dataset is
checked into the repo as static assets, and the browser keeps its own copy in IndexedDB.

- **Dataset** — 10 `.txt` files in `src/assets/dd-chords/` (~20 KB total), format documented by the parser in [`src/music/music.ts`](../src/music/music.ts): `#title …` / `#performer …` meta lines, chords wrapped in `<…>`, `~` for indented lines.
- **Index** — `src/assets/dd-chords/dd-chords.json`, `{files: [{hash, path}]}`, md5 of each file's text. Generated by `generate-chords-index.js` during `prebuild`; **gitignored**, never hand-edited.
- **Storage** — IndexedDB `ddchords` v5, one object store `tracks`.
- **Hosting** — Firebase (`https://dd-chords.web.app/`), deployed by Travis on `main`.

## Data flow — asset → IndexedDB

The entire load path is one directive:
[`TrackImportWatchDirective`](../src/app/shared/track-import-watch/track-import-watch.directive.ts),
applied on `<router-outlet>` in [`app.component.ts`](../src/app/app.component.ts).

```
DiOnline (snapshot of navigator.onLine) → filter(online)   ← offline: skip everything
   ↓
HttpClient 'assets/dd-chords/dd-chords.json'
   ↓ combineLatest
DiCurrentTrackHashes take(1)               ← Set of hashes already in IDB (hash index)
   ↓ mismatched hashes only
concatMap fetch '<path>' as text           ← bufferCount(paths.length): one emission, the whole batch
   ↓
TrackService.saveTrack$('builtin', dataToTrack(text))
   ↓
upsertTrack$ — skips if hash unchanged, otherwise re-writes the row
             and keeps oldTrack.playlists   ← user favourites survive
   ↓
DiMusicIdbChange.next() → DiMusicIdbLive → views re-read
```

Empty index → throw `'Local sync aborted (no index or files found.)'`; a failing fetch → per-file `false`.
Both go through `LoggerService` only — a broken sync never reaches the UI, so a bad `dd-chords.json`
looks like "nothing to import".

Sharing is separate from that sync: the `/shared` route (`SharedTargetComponent`) reads `?<id>=…`
(`QueryParamTrackId`) and redirects to `ui/tracks/<id>`, or `ui` when the query is empty. The share
button in `track-meta.component.ts` is gated on `DiCanShare`.

### Storage

[`src/music/music-idb.ts`](../src/music/music-idb.ts) — framework-free rxjs wrappers over raw IDB
callbacks (`idbOpenRequest$` from `src/indexeddb`). `IdbTrack = Track & {source, timestamp}`;
indexes on `hash`, `id` (primary), `performer`, `performerHash`, `source`, `timestamp`.
Playlists are a single string, `<|>#favorites<|>…`, queried by substring — see `playlistToQuery`.

Reading goes through `TrackService` (`src/app/shared/track/track.service.ts`) and the `Di*` tokens,
never straight at `music-idb`. Writes are `saveTrack$` / `saveTracks$` / `toggleTrackFavorite$`.

### Offline

The gate is `DiOnline` = `of(!!navigator.onLine)`: a snapshot taken at subscribe, never a live stream.
The directive subscribes once — at `AppComponent` creation — so a page that loads offline can never
sync later, and [`ngsw-config.json`](../ngsw-config.json) caches `/assets/icons/**`, fonts and images
but **not** `/assets/dd-chords/**`. A cold offline install has no data and no way to resync. That is
milestone M1 in the ledger.

## App composition

Angular 22, `bootstrapApplication` in [`main.ts`](../src/main.ts) — standalone only, no `NgModule`,
`provideZonelessChangeDetection`. `provideServiceWorker` is enabled only in production,
and the root router (`'ui'` → dashboard, `'shared'` → share target, `''` → redirect `'ui'`) is set up
with `withComponentInputBinding()`. `provideAppInitializer` wires `CacheService` before bootstrap.

```
main.ts → AppComponent
  ├── <router-outlet [ddChordsTrackWatchImport] [ddChordsServiceWorkerWatch]>
  └── routes
        ''            → redirect 'ui'
        'ui'          → DashboardComponent      (lazy)
              'info'   → InfoComponent
              'tracks' → MusicComponent        → ':idTrack' → RoutedTrackComponent (lazy)
        'shared'      → SharedTargetComponent   (share-target page)
```

`MusicComponent` switches between the performers and tracks lists with local `signal()`s, and a
selected song renders into its nested `<router-outlet>` via the `:idTrack` child route — so a track
permalink is `ui/tracks/<idTrack>` and the visibility of each pane is derived from route params.

Route/query names are constants in [`src/app/routing.ts`](../src/app/routing.ts); each feature has
`routes.ts` with lazy `loadChildren`/`loadComponent`.

### State: `Di*` injection tokens

`src/app/di/*.di.ts` — `providedIn: 'root'`, factory returning an `Observable`. Composition, not
a store. `src/app/di/active/*` holds the mutable, user-driven inputs (`StateSubject`s:
`DiShowChords`, `DiShowFavorites`, `DiTracksFilterQuery`, `DiTracksFilterPerformer`,
`DiPerformersFilterQuery`, `DiCanShare`). Everything else is derived:

- `DiMusicIdb` → open DB once; `DiMusicIdbChange` (a `Subject`) → `DiMusicIdbLive` re-emittable handle.
- `DiCurrentTrackHashes` / `DiCurrentTrackMetas` / `DiCurrentPerformers` read from `DiMusicIdbLive`.
- `DiTracksFilterPart*` → `DiTracksFilter` combines the filter parts for the list views.

Views are `OnPush`; app state is rxjs everywhere except one place:
[`MusicComponent`](../src/app/feature/music/music.component.ts) holds its two panes as
`signal()`s — the only signals usage in `src/`.

### Persistence of UI state

[`CacheService`](../src/app/shared/cache/cache.service.ts) keeps `dd-chords-cache` in localStorage
(versioned, `cachedMapVersion = 2`). Registered keys: `showChords` and `showFavorites` from the app
initializer in `main.ts`, `logs` from `LoggerService` — nothing else is persisted.
Note the precedence bug (`?? 0 >= …`) tracked as M3.

### Service worker

`ddChordsServiceWorkerWatch` ([`service-worker-watch.directive.ts`](../src/app/shared/service-worker-watch/service-worker-watch.directive.ts))
listens to `SwUpdate.versionUpdates` (`VERSION_READY`) and `SwUpdate.unrecoverable`, waits 5s, then
`activateUpdate()` and a full `document.location.reload()`. There is no prompt UI. `provideServiceWorker`
is `enabled: environment.production`, so in dev builds nothing is registered and the directive stays quiet.

## Tests

Config in root `jest.config.ts` (`jest-preset-angular` CJS preset, `moduleNameMapper` for `src/*`,
reporters `default` + `jest-junit` → gitignored `junit.xml`). Setup is `src/jest-setup.ts`, which calls
`setupZoneTestEnv()` even though the app is zoneless, and imports `src/jest-global-mocks.ts`: that
throws on `console.error` and pins `Date.now` / `Math.random` and `localStorage`/`sessionStorage`, so
a test that logs or free-runs fails. Three specs (`app.component`, `music`, `md5`) with ng-mocks +
`toMatchSnapshot()`, snapshots in `__snapshots__`. Regenerate with `pnpm run test:dev`.
